- `integration/optr_capture.py:_gate_hook` extracts interleaved per-head Q/gate exactly as native `references/vllm/vllm/model_executor/models/qwen3_next.py` and `references/vllm-ascend/vllm_ascend/patch/worker/patch_qwen3_5.py`. The attention hook receives post-normalization/post-RoPE Q/K and pre-gate native output. `project_output` applies the BF16 gate-product rounding before W_O. I did not find a source-proven Q/gate indexing or pre/post-gate teacher bug.
- W_O is the real native BF16 row-parallel shard. Layer samples verify rank/head/token/frame/position identity before summing all head contributions. Complete K/V, not sparse K/V, is retained. The frame endpoint is always sampled.
- The bundled GPQA CSV contains 198 messages; canonical deduplication and sorted round-robin assign 66 records to each split. Initialization uses train only. Current source does not use test records for gradient fitting. This verifies record-identity separation, not semantic independence or absence of pretraining contamination.
- Spawn isolation, post-warmup hook installation and cleanup ownership are present. These are source properties; they do not constitute NPU lifecycle validation.

## Material limits and improvement points

1. **The comparison seed is not the existing OSCAR recipe3 baseline.** `optr_oscar_seed.py:52-64` turns recipe3 metadata into a recipe6 shared-per-layer, zero-mean, FP32-statistics seed using only the first 512 aligned train rows. Existing OSCAR uses per-head centered recipe3 over its calibration budget. A gate that improves this new seed cannot establish improvement over the user's OSCAR. Preserve an authenticated actual OSCAR artifact as an explicit comparator, and distinguish seed-improvement from OSCAR-improvement in the certificate. Do not claim the seed name alone proves equivalence.
2. **Three requests per split are strongly correlated.** `tools/calibrate_optr_traces.py:20-50` concatenates the 66 rendered records once, then builds every length from index zero of the same periodically repeated stream. Therefore 4K is exactly the prefix of 32K and 32K is exactly the prefix of 64K, for any valid tokenizer. The nine request IDs are not nine independent natural conversations. `source_record_sha256` lists the whole split even when the truncated prompt only consumes its first records. Preserve source identity, but report the actually consumed record spans and repetitions separately.
3. **Packing can stop inside a record.** Each source record already includes `add_generation_prompt=True`; concatenating those rendered prompts and truncating at an arbitrary token can create artificial chat boundaries and place the 8 generated tokens after a partial question. This is useful stress coverage, but weak evidence of ordinary instruction/answer behavior. A better versioned plan should include complete natural prompt terminals and separate real long-context material, deterministic nonzero starts, multiple requests per length, and explicit actual-record provenance. It must remain separate from benchmark evaluation data and from inference routing.
4. **Very sparse query / short-generation coverage.** With full 16K prefill chunks, each split samples only 80 query positions (56 prefill and 24 decode) from 102,424 executed positions; exact counts depend on the native scheduler and must be read from actual manifests. The default policy observes only eight generated decode forwards per request. About 30% of the idealized sampled rows are first-prefill rows with no compressed history. Keep first-prefill rounding checks, but separately measure historical INT2, terminal-answer and later-generation error. A longer/disjoint calibration plan may improve coverage but is not itself proof of score improvement.
5. **PC/MTP/concurrency are not captured.** `tools/calibrate_optr_traces.py:123-138` explicitly uses BS1, eager, PC off, no speculative_config, and short native greedy generation. Chunked prefill is captured. This does not validate reused-prefix boundaries, mixed-batch split geometry, q4 MTP verification/rejection trajectories, or accepted-token effects. Existing runtime compatibility tests remain necessary and are separate from these trace certificates; do not label `captured_runtime_frames` as all serving schedules.
6. **Independent local layer replay omits accumulated distribution shift.** Every layer consumes native Q/K/V, gate and teacher recorded from an entirely native model. Deploying changed rotations at all FULL layers changes later hidden states, QKV/gates and generation. Lower independent layer SSE cannot imply lower final-logit error, higher answer accuracy, or better MTP acceptance. A future genuine quality gate must compare actual loaded OSCAR and OPTR artifacts end-to-end on a held-out set, with identical generation settings; local tests should remain labeled local.
7. **Output rounding views are explicit approximations.** `optr_traces.py:446-471` derives FP32 W_O products and CPU FP64 TP sums, then evaluates two BF16 casts. It does not capture actual native post-W_O/HCCL output. The existing comments correctly state this limitation. If diagnosing an NPU discrepancy, add an isolated capture of the real projected teacher/output rather than claiming the views reproduce the closed GEMM/reduction order.
