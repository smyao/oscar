## 已改动的行为

- 单独计算 OptR 准备预算，按模型 FULL 层数、KV 头数和固定拟合步数缩放，当前 16 层 × 4 头 × 16 steps 的总上限为 86400 秒。它是有限预算，不是耗时预测。普通构建、探针及服务时限仍为原值；嵌套 BF16 正确性入口的父阶段同步放行准备预算，避免父进程先误杀。
- CPU 拟合内每个训练 step、验证请求及阶段边界输出实际进度；精简终端模式也显示这些事件。连续默认 1800 秒无真实进展则报告最后的层、头、阶段并终止准备，固定启动器清理所属进程组。外层每分钟心跳不能续期。原生采样和 recipe3 准备子进程仍各有原来的有限时限。
- 完成头原子保存；完成层只有通过联合 validation 和独立 test 才保存。恢复身份绑定基底 PT、trace manifest、完整 profile、模型层/头/维度、拟合实现哈希及 test-only 标记；文件哈希、正交性、均值、证书和非劣条件重新核验。头断点不是整层通过凭证。最终发布前仍验证完整所有层，失败不启动正式服务。
- 保留完整原生 trace 的原有身份及路径。本次已完成的 7 请求在配置、模型与文件匹配时自动复用，不重采样。旧版本没有保存头断点，因此这次中断前未落盘的拟合工作无法找回；新版本此后的中断只需重做未完成的头。已验证整层可以直接恢复并完成最终发布。
- 离线验证复用固定侧历史旋转/量化和 teacher 投影；变量侧完整历史每候选、每样本只算一次，不再按 query microbatch 重复。保留原 microbatch 形状、浮点归约顺序、16 steps、所有 4K/32K/64K 样本、分片及质量门；完整优化配对测试中 Rk/Rv 与选择记录逐位一致。

新增断点文件与 CPU 缓存只属于离线准备。线上 attention、INT2 codec、KV 布局、runtime、MTP/GDN/prefix/graph、timer、服务 argv 和设备配置均未修改。不新增在线计算或 KV 显存。CANN 源与构建签名逻辑保持；上次有效编译产物按原规则自动复用，无需手工删 build、删 PT 或修改超时。

原生 vLLM 图编译缓存与 CANN 产物是不同缓存：现有规则将整个插件 Python 源绑定到图缓存身份，本次更新仍可能自动选择新的图缓存目录并重新编译图。没有削弱该规则来复用旧图，也不把准备/首次图构建成本算作零；后续相同源码与配置按原规则复用。
