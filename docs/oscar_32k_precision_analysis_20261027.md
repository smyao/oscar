# 当前 OSCAR 32K 精度损失分析与改进方案

日期：2026-10-27。分析基底：`oscar-new-4`，提交 `c271083efed8b4fb0ae496ecfe42179c4dbfa8f7`。

**当前最值得优先处理的是校准分布与真实长上下文的差异，以及以局部误差代理代替模型质量的选择方法；同时，长历史算子和缓存生命周期的设备正确性仍需保留为独立排查方向。现有证据不足以把剩余损失全部归因于 INT2，也不足以认定某个内核已经解释了全部分差。**

本文围绕用户提出的 32K 数据集精度问题展开，结合工程已有 LongBenchv2 记录分析。当前消息没有提供本次逐题结果、分数和实际加载产物身份，因此旧版本的“约 3 点”“约 10 点”和历史 127 题结果均按各自时间与版本使用，不作为当前提交的新测量。

本次只增加分析报告与证据摘要，没有修改推理实现、配置、timer 或参考树，没有连接真机、运行模型评测或性能实验。源码配置核验与 7 项既有 CPU 测试结果保存在 [本次证据摘要](../reports/precision_analysis_20261027/evidence.json)。

**一、先明确论文结果能够支持什么判断**

这里讨论的是 FutureMLS-Lab 的 *Offline Spectral Covariance-Aware Rotation*，论文编号 2605.17757，不是名称相近的另一篇 OScaR。

该论文主表中，相对 BF16 的五任务平均分差分别为：Qwen3-4B Thinking 下降 3.78 点，Qwen3-8B 下降 1.42 点，Qwen3-32B 下降 0.02 点。主表的 32K 是最大生成长度；它不等同于当前模型的 32K 长输入 LongBenchv2。论文采用 MMLU 风格的 8878 token 校准，理论也明确限定在具有假设的误差代理上，没有证明完整自回归过程无损。因此，“小于 1 点”应作为本工程目标，不能视为算法对任意模型和任务的保证。[论文实验设置、表 2 与局限性](https://arxiv.org/html/2605.17757v1)

这不降低当前质量目标：**如果相同模型、相同输入和生成设置下，加入 OSCAR 后稳定下降，就仍然需要解释并改善。** 只是需要用本工程自己的同参 native 结果衡量，而不是套用另一个模型的论文均值。

还应分清“论文配方”“官方某个版本的默认启动配方”和“官方结果表实际使用的 PT、clip 表”。项目先前对固定官方版本 `38680852` 的审计发现，启动校准、预生成 RotationZoo 产物、逐头 center 结果配方并非同一个概念。当前没有经过认证的同模型官方发布 PT 与逐头 clip 表，不能仅凭 `qqt_sst` 或 `perhead_center` 名称宣称已经复现其质量。[官方配方审计](../reports/official_semantics_audit_20261021/calibration_audit.md)

**三、可能原因的优先级**

下表的“优先级”表示调查和改进的价值，不是已经测得的因果占比。

| 原因 | 当前证据强度 | 判断与优先级 |
|---|---|---|
| 短 prefill 校准未覆盖长位置、暖 prefill、decode | 采样代码直接确认；是否能泛化及对当前分差的贡献未测 | 高优先级，最有价值的算法改进方向之一 |
| 固定 clip、INT2 四级表示与目标分布不匹配 | 固定参数与真实 selector 反例均确认 | 高优先级，但禁止再次只按代理下降上线 |
| 当前运行的配置/PT/动态库不是预期版本 | 本地选择已确认，现场身份未确认 | 最先做已有证据核对，成本低；不等于认定错加载 |
| BF16 旋转、P 舍入、跨 tile/split 归约影响 | 数值机制存在，局部反例存在 | 中高优先级，先量实际误差，再决定是否改算法 |
| 长 history、C16、图回放或 DMA 生命周期错误 | 既往有同类事故；现有覆盖有缺口 | 中高优先级的正确性风险，不能凭 CPU 通过排除 |
| 窗口与 chunk 生命周期不同于官方 | 已有固定版本审计 | 中优先级，需按实际缓存状态比较，不凭名字调窗口 |
| GQA 聚合、长文档语义检索与校准目标不一致 | 数学上成立，缺本模型逐头输出证据 | 与校准、clip 联合研究 |
| TP、eigh 特征基、BF16 矩阵正交残差 | 存在实现差异与代数反例 | 次级方向，不能据此断定 CPU FP64 拟合有错 |
| MTP 或 APC 自身必然降低模型精度 | 不成立；应检查具体提交/回滚/状态错误 | 条件性排查，不默认关闭功能 |
| thinking/采样等评测条件不同 | 先前记录称用户已确认一致 | 低成本核对已有记录，不反复要求用户证明 |

**四、为何校准覆盖不足是首要候选原因**

当前 [校准入口](../tools/calibrate_model_rotations.py) 具有四个确定行为：

1. 默认读取 GPQA 短题，累计完整 prompt，直到接近 30000 token。
2. 每题独立执行、位置从该题开头开始，不会把所有题组成一条 30K 上下文。
3. eager、单请求、关闭 chunked prefill，每条 prompt 必须装入一个 prefill chunk。
4. `max_tokens=1` 只从 prefill logits 采样，不产生后续 decode forward，也没有 MTP 校准。

所以 **30000 token 是总样本预算，不是上下文长度覆盖**。把这个数字调大，只可能多采一些相同类型短题，不能自动获得长上下文统计。现有入口还会拒绝超出单 chunk 限制的 prompt；长校准需要新的采样协议，不能仅改 JSON 数字。

旧失败日志曾记录99题、29867 token、最长输入约847 token。该次校准随后失败，这只能说明默认语料的输入性质，不能当作当前成功 PT 的实际长度分布。[既有校准审计](qwen38_precision_audit_20261020.md)

这会带来几类可能的分布偏移：

| 偏移 | 为什么会影响量化 | 应观察什么 |
|---|---|---|
| 长位置与相对位置 | post-RoPE Q/K 的方向统计随位置组合变化；短题中的优势方向未必适合远距离检索 | 按 query/key 位置及距离分桶的 score 与输出误差 |
| 短问答与长文档 | 长文档有大量相近干扰项、少量关键证据；均值统计可能淡化稀有重要方向 | 检索命中 token 的注意力质量、强干扰项排名变化 |
| 冷 prefill 与暖 prefill | 后续 chunk 读取量化历史，且上游层输出已经受此前误差影响 | 首个/后续 chunk 的层输出与同前缀 logits 差异 |
| prefill 与 decode | 答案/推理 token 的 query 分布不等同于输入文档 token | decode 位置分桶的 top-token margin、KL、输出漂移 |
| 原生激活与量化闭环激活 | 当前用原生模型采样；实际服务较高层接收的是已受前层量化影响的状态 | 相同前缀下逐层首次显著偏离位置 |

不能把这些直接写成当前根因。项目对官方固定源码的既有审计已经确认：**官方 startup 同样是短题、prefill-only**。因此这里是共同的泛化风险，不是简单的“本地少执行了官方一个 decode 步骤”；而官方发布 PT 是否使用同一采样分布仍未确认。[采样公式与官方对照](../reports/official_semantics_audit_20261021/calibration_audit.md)

改进应采用按长度、位置和阶段分层的校准：短、中、长文档均保留；覆盖8K/16K/32K位置、跨chunk历史、少量答案或推理阶段query。校准语料应独立于最终验收题及答案。预算固定时，优先提高覆盖而不是无选择增加 token；避免长文档凭 token 多就完全主导协方差。

MTP草稿层需要独立统计和身份，不能拿目标 FULL 层矩阵直接套用。其优先级低于目标模型链路，因为草稿质量变化首先影响接受率，不能自动推导为最终答案分差。

**五、clip 与代理目标为何可能“越优化越差”**

当前 [writer](../csrc/kernels/store_aligned_int2.cpp) 在旋转后的每行按绝对值选阈值，先裁剪，再用 min/max 做四级非对称量化。它没有直接优化最终答案，也没有保证被裁掉的维度对 query 不重要。

对 D256，当前 K=.96 选择第246小的绝对值阈值，最多截断10个更大的坐标；V=.92选择第236小的阈值，最多截断20个。并列值会减少实际截断数。这里的“96%”不是保留96%的注意力信息，也不是固定幅值乘0.96。

设一行注意力为 `p=softmax(z)`、`z=qKᵀ/√D`、`o=pV`。一阶扰动近似为：

```text
δz = q·δKᵀ / √D
δp_i ≈ p_i · (δz_i − Σ_j p_j·δz_j)
δo ≈ δp·V + p·δV
```

这说明 K 的重要性取决于当前 query、竞争 key 和 V；V 的重要性取决于实际注意力权重。平均重构误差更小，不保证关键检索 token 排名更好，也不保证最终输出更好。不同来源若存在不同偏置，历史与精确窗口间的相对概率也会变化；只有所有可见 key 的公共 logit 平移才会被 softmax 抵消。

项目已有确定性反例，且本次重跑通过：真实 recipe4 selector 把 clip 从 .96 选到 .94，四项 score 代理均改善，但 attention 输出由准确的1.0变成约0.761594。该反例隔离了选择方法的缺陷，不能用于计算用户约10点回归的占比。[反例测试](../tests/test_clip_proxy_attention_counterexample.py)

**现有样本还有一个关键限制：** [累积器](../oscar_ascend/rotation_calibration.py) 保存每头 `q_gram` 和逐 token K/V，没有保存逐 query Q。它适合重拟合现有协方差矩阵，却不足以恢复真实的逐 query 因果 attention。因此“继续复用旧样本”可以用于当前 recipe 拟合，不能宣称已经能够做完整的 attention-output 校准。

建议的新选择方法：

- 用有界抽样的真实 Q，连同 prompt身份、绝对位置、所属KV头、因果可见范围和来源状态，补充校准记录。只保留必要 query，避免全量 attention 矩阵。
- 在独立留出样本上比较真实 `softmax(QKᵀ)V` 的输出误差，并同时观察检索排名、历史/精确窗口概率质量、尾部误差。
- 分开检查 K-only、V-only 与二者联合变化，避免改善 K 重构却增加 V 偏差或联合非线性误差。
- 对 GQA 的各 query head 保留分项指标。当前每个 KV 头服务多个 Q 头，仅优化平均协方差可能牺牲少数敏感 Q 头。
- 在有可复用模型证据时，再检查同前缀 logits KL、答案候选 margin 和实际任务变化。即使真实局部输出误差下降，也不是整模型准确率的充分条件。
- 新参数只有在预先定义的留出门通过后，才成为候选；模型质量未确认时保留独立研究配置，不再次自动替换 recipe3。

不建议现在直接把 clip 改成1.0、重新启用recipe4或寻找一个“万能比例”。少裁剪会扩大动态范围，四级表示对大量普通值的误差可能反而增加。

**六、反量化修复以后，数值损失仍可能来自哪里**

**1. 已修复的 metadata 舍入应从当前首要嫌疑中移出。**

旧 mode1 会先将 metadata 和减法结果舍入到 BF16。真实 CPU 核反例中，原本可准确表示的 K 两档1.0/1.0078125被读成1.0/1.015625；对应合并输出由解析值0.6偏到0.5796245。mode0恢复为0.60000002。当前 candidate 已在 decode、MTP 和 capture 统一 mode0。[读端策略](../oscar_ascend/integration/aligned_math.py)、[真实CPU证据](../reports/logic_precision_20261023_extended/README.md)

这证明“FP32 metadata 保存了却又在读端提前降精度”会造成额外误差；不证明当前余下损失仍由它导致。mode0也不是对任意原始激活误差单调下降的数学保证。

**2. BF16 旋转不是精确正交变换。**

理论上 `RRᵀ=I`，但保存/加载到 BF16 的矩阵 `R_b` 通常只有近似正交性。再加上 Q、K、V 旋转结果的 BF16 舍入，即便不做 INT2，旋转与逆旋转也可能相对 native 产生偏差。当前统一坐标域避免了“同一个 key 因来源不同而用不同数学”的额外问题，但不会让这部分误差消失。[当前旋转与最终输出链](../oscar_ascend/integration/official_math.py)

建议先对实际 PT 检查 `||R_b R_bᵀ−I||`、逐头旋转往返误差，以及相同模型激活上的“只旋转、不量化”离线误差。若它明显小于 INT2 误差，就不应把重心放在旋转精度。若确为主要来源，才研究独立版本的高精度旋转或补偿矩阵；后者必须完整定义 Q/K、V/O 的成对变换，不能只把某个转置替换成逆矩阵。

**3. P 舍入与 FP32 分母存在有限精度差异。**

当前 C16 的 online max、sum、alpha 和累积状态是 FP32；但 softmax 产生的概率权重在 Cube PV 前转为 BF16。因而分子使用舍入后的权重，分母仍来自 FP32 softmax。即使 V 恒定，结果也不必严格等于该常量。已有多tile CPU记录中的2.996892与理论3就能由这条链解释。[C16实现](../csrc/kernels/attention_cv_official_cluster16.cpp)、[多tile复核](oscar_logic_review_20261023.md)

这不是“softmax被改为BF16”，也不构成应改分母的理由。分母、LSE和跨split合并是一个整体，单独改归一化可能产生新偏差。只有实际模型输入证明它是主要误差源后，才考虑独立的PV精度/概率补偿方案，并保留现有合同作为对照。

**4. 小矩阵误差不能机械乘成32K损失。**

32768个key按KV256划分约有128个计算tile，实际还受sink/window/current和split影响。更多tile意味着更多online更新与边界组合，但舍入可以相消也可以相关，不能把某个tile误差乘128，或把一次输出误差换算成若干准确率百分点。

应检查不同split、C1/C4/C16路由、padding与尾tile对同一逻辑输入的结果差异。若误差随路径突变或出现固定边界跳变，应优先怀疑实现；若只随激活分布和量化强度平滑变化，更支持算法误差假设。

**七、32K 特有的算子与缓存风险不能被短测试覆盖**

现有证据已经验证若干跨KV256的CPU病例，没有发现那些病例中的alpha/旧累积值更新错误。后续R256扩展中，q4完整路径通过，C16 history-only得到有效数值证据；但完整C16、context944/recent256病例曾在180秒时限内未完成，不能把隔离结果记为完整路径通过。更不能称为目标NPU上的32K图回放验收。[扩展检查明细](../reports/logic_precision_20261023_extended/README.md)

建议将正确性风险分成两个问题：

| 问题 | 关键边界 | 为什么与精度有关 |
|---|---|---|
| 数学状态更新 | 多次max抬升、窄/宽logit、非恒定V、强抵消、全masked尾tile、跨split | 错误alpha或空段合并会改变历史权重 |
| 数据生命周期 | 跨DMA覆盖、页复用、跨请求共享、MTP接受/拒绝、固定图地址换输入、graph padding | 可能读取逻辑上不属于本请求/位置的KV或状态 |

档案#145已有“CPU同形通过，NPU发生UB异步覆盖”的先例。因此CPU、CANN编译、真实NPU、图捕获、图回放和模型质量必须分列，不能互相代替。status=0只能说明相应检查未报错，不能证明有限的错误数值不存在。[档案](../issue1_full_record.md)

本次不认定这些缺口就是当前损失原因。它们的意义是：在把所有剩余分差归为“2bit上限”之前，还不能跳过这层正确性证明。

窗口方面，当前fixed-per-forward映射与官方8-token flush、非final/final-prefill策略不完全相同。更多精确token不一定使最终答案单调改善；关键是每个历史位置究竟读取哪一份表示，是否在正确的提交代际，是否无缺失/重复。不能仅把recent从256改成263就声称对齐官方。[窗口生命周期审计](../reports/official_semantics_audit_20261021/window_policy_audit.md)

MTP必须区分草稿接受率与目标模型正确性：若验证、位置、提交和回滚正确，草稿更不准通常先体现为效率下降；若出现错误提交、错误mask或被拒绝token残留，才可能污染最终输出。保留MTP3并验证这些不变量，比默认关闭MTP更符合当前问题与工程约束。

APC也一样：miss通常意味着重新计算，不能单凭命中率低解释精度差；命中位置与GDN状态不一致、错误恢复或共享页串用才是质量风险。显式APC开启的运行要与默认关闭的运行分开归因。

**八、其他值得保留、但不宜抢先修改的可能性**

**统计目标本身是近似。** 当前V旋转使用原始K的 `kᵀM_qk` 能量加权V二阶矩，并不是逐query的精确softmax敏感度；center以后仍保留该权重定义，与既有官方审计一致。不能因看到“没有重算中心化后的权重”就认定bug。若要换成真实attention敏感度，它属于新的研究配方，需要独立评价。[拟合源码](../oscar_ascend/rotation_calibration.py)

**CPU与GPU的合法特征基可能不同。** `eigh`的特征向量符号以及接近重根时的子空间基不唯一；经过Hadamard混合与非线性量化后，两个数学上合法的基也可能产生不同重构结果。项目已有D8代数反例，说明“协方差公式一致”不保证PT逐值一致；它不证明CPU FP64不准确。优先比较子空间、特征残差和留出attention质量，避免凭一个符号规范化规则改生产。[特征基审计](../reports/official_semantics_audit_20261021/calibration_audit.md)

**GDN可能传播上游误差，但不能据此认定native GDN错误。** OSCAR改变FULL层输出后，后续包括GDN在内的层会接收不同隐藏状态。这是模型内传播路径，不是擅改GDN状态精度的依据。先前“HF声明FP32 SSM，所以本地BF16必然错误”的判断已经被目标原生能力证据纠正，不应重提为修复方案。[已纠正结论](qwen38_precision_audit_20261020.md)

**模型名、TP数相同不等于激活逐值相同。** 原生后端、矩阵乘法归约、tokenizer/template、模型revision、权重量化都会影响校准样本或评测。当前代码已加强模型/PT身份绑定；正常一键配置没有发现W8A8专属补偿遗漏。除非已有运行记录显示不一致，不应再次把这些已修问题当成已确认主因。

**九、改进方案与成本取舍**

建议先完成不改变表示能力的改进，再考虑增加存储精度。下列为方案评估，本报告没有启用新配置。

| 顺序 | 方案 | 预期解决的问题 | 成本与实施条件 |
|---|---|---|---|
| P0 | 用已有产物绑定运行身份和分数 | 排除旧PT、旧动态库、旧策略与新代码混用的归因错误 | 复用已有启动日志/effective-target/PT manifest，不恢复重型默认审计 |
| P1 | 分层长位置校准，保留必要Q样本 | 短题统计不能覆盖长历史和decode | 增加一次性采样/离线拟合成本；新recipe与采样profile，旧PT不改标签 |
| P1 | 以留出attention输出和尾部风险选择clip | 重构/score代理改善却伤害真实attention | 增加离线比较成本；K/V联合验证；不能仅凭校准集上线 |
| P1 | 补多tile、R256、C16、图及生命周期边界 | 排除长路径实际实现错误 | 首先复用已有结果，只补缺口；独立正确性门，不改timer |
| P2 | 对实际PT分离旋转、INT2、P舍入误差 | 确认有限精度预算花在哪里 | 离线/有界功能比较；主要误差确认后才改相应算术 |
| P2 | 研究窗口策略或适度增加保护 | 关键token过早进入低精度历史 | 改变存储/生命周期与容量；需独立合同，不能直接调整当前窗口 |
| P3 | 更小量化group，如D256拆两组128 | 每行四档不能同时兼顾多种幅值分布 | 增加metadata、writer/reader开销及新cache ABI |
| P3 | 少数敏感层/头使用INT4或异常值补偿 | INT2在特定头存在难以消除的表示误差 | 属格式扩展，改变压缩收益与路由；不能作为静默fallback |

量化group与KV计算tile要分开：把KV计算tile从256改小，主要改变执行与归约；把量化group从256改为128，才会给同一K/V行增加scale/zero组数。不能用前者冒充后者。

以下仅为D256每token、每KV头的K+V**逻辑历史字节账**。假定每组每侧仍保存两个FP32 metadata，未计物理页padding、GDN、图workspace、窗口快照或MTP临时数据：

| 表示 | K+V payload | metadata | 合计 | 相对纯BF16历史的逻辑压缩 |
|---|---:|---:|---:|---:|
| BF16 | 1024B | 0B | 1024B | 1倍 |
| 当前INT2，group256 | 128B | 16B | 144B | 7.11倍 |
| 提案INT2，group128 | 128B | 32B | 160B | 6.40倍 |
| 提案INT2，group64 | 128B | 64B | 192B | 5.33倍 |
| 提案INT4，group256 | 256B | 16B | 272B | 3.76倍 |

在32768位置、仅考虑64+256个精确token的理想逻辑账中，当前压缩约为6.71倍，而不是完整系统8倍。真实容量还取决于物理布局，不能从这个数字推算实际batch或性能。group128相比当前历史字节增加约11.1%，因此它是值得评估的精度/容量折中，但不保证比分布更合适的group256更准。

若采用更大窗口或混合位宽，必须重新计全部KV与相关状态成本；本轮冻结的窗口、INT2格式、argv和候选入口保持不变。这些结构性选项只在前述低成本方向不足时进入独立后续范围。

**十、如何区分真正根因，避免再次盲改**

第一步先消费已有证据，不要求重跑AISBench。把已有每次分数与提交、effective-target、PT指纹、recipe、clip、读端policy、实际动态库和生成配置对应起来。不能将“checkout已经更新”当作运行worker已更新；也不能把日志中的模型名当作权重身份。

对已有逐题结果，优先统计：native正确而OSCAR错误的题、反向恢复的题、答案抽取失败、超长截断、请求失败、长度/题型分布。对于工程历史127题集合，一题约0.7874个百分点；约3点只是约4题净差，约10点约13题净差。这个离散性不能证明差异来自随机性；若缺逐题配对与seed记录，就不能给出可靠的配对显著性结论。不同版本总分相减，也不能知道是否在同一组题上发生退化。

第二步采用相同输入的分层参照，避免所有误差混在一起：

| 参照 | 定义 | 主要回答的问题 |
|---|---|---|
| A | 相同真实Q/K/V上的未量化attention | 未压缩的局部目标是什么 |
| B | 相同token集合，执行实际BF16旋转/中心化，但离线不做INT2 | 旋转、中心化舍入与逆旋转本身损失多少 |
| C | 相同集合与窗口策略，独立数学实现当前clip/INT2和读端规则 | 算法表示误差与窗口策略造成多少差异 |
| D | 当前实际writer→reader→merge→inverse | 实现是否兑现C，是否存在路由/状态/设备错误 |

这些是离线或有界验证参照，不是生产fallback，也不允许在推理热路径全历史恢复。A到B、B到C、C到D的差异可用于逐层归因，但准确率是非线性终点，不能把各项数值误差直接相加成分数占比。

第三步，在已有可用模型激活或未来获准的有界采样中，使用固定前缀的teacher forcing比较逐层输出与logits。自由生成一旦早期token分叉，后续上下文已经不同；只比较最终文本无法分清“第一处数值错误”和“正常的分叉放大”。固定前缀用于定位，真实生成结果用于最终质量，二者都不能替代另一方。

建议保留的决定性指标包括：按layer/KV head/Q head、位置、距离和source划分的误差；attention输出相对L2及p95/p99；历史与精确窗口的总概率偏差；关键检索排名；同前缀logits KL和候选答案margin；不同split/路由/图输入下的输出与状态一致性。均值以外还要看最差桶，避免少数重要头被平均值掩盖。

可采用以下判断规则收敛方向：

- C与D不符，且随C16、split、页边界或graph变化：先修实现，不调clip。
- B相对A已出现主要偏差：先研究旋转/中心化有限精度，不能只怪INT2。
- C相对B明显退化，且集中在长距离检索或特定头：优先校准覆盖、clip目标和group设计。
- 局部比较都合理，但自由生成恶化：检查跨层闭环、低margin token及评测输出规则，不能宣称内核无误就等于模型无损。
- 仅APC命中或MTP拒绝后异常：检查对应状态生命周期，保留原生功能契约。

这套顺序可以由开发过程内部完成，继续保持最终固定candidate入口；不把诊断负担转给用户，不要求重复已经完成的AISBench。新模型采样和设备证据若尚不可用，应保留相应结论为假设，而不是用人工样本代替真实质量证明。

**十一、建议的验收标准与本次结论**

验收应至少分三层，分别记录：

| 层级 | 应满足的条件 | 不能被什么替代 |
|---|---|---|
| 实现正确性 | 冻结合同、metadata/status/mask/ownership、必要NPU与图边界通过 | 编译成功、CPU通过、HTTP200 |
| 量化质量 | 留出数据的attention/logits指标改善，无关键桶明显恶化 | 校准集平均重构误差、selector分数 |
| 任务质量 | 同模型同设置同数据的实际分差达到既定小于1点目标，并说明样本量与随机性 | 短probe、人工反例、论文其他模型结果 |

当前已经修复或撤回的主要问题，应保持其成果：recipe3逐头中心化、统一旋转域、合并后一次逆旋转、FP32 metadata读端、recipe4撤回。继续在这些已明确的基础上工作，比把旧问题重新列成当前根因更有效。

**建议下一轮首先做“长上下文分层校准与留出attention目标”，同时补上长路径正确性缺口；在证据表明纯INT2表示能力不足后，再讨论group128、窗口保护或混合精度。** 不建议马上大改CANN、全切FP32、放宽容差、关闭MTP/APC、恢复recipe4或修改timer。现有证据可以确定这些方向的合理性，还不能保证任何单项方案一定追回剩余分数。

本次实际完成的本地检查为：两个既有测试文件共7项通过，验证clip代理反例、FP32读端反例和overlay合同；没有新的模型、NPU、图或速度验收。
