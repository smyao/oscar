# C16内部计时实验：把约1199 ms继续拆到小步骤

```bash
git pull --ff-only && bash scripts/test_c16_breakdown.sh
```

这个入口只启动一次OSCAR服务，做一个短预热，再发**一条32K输入、默认16输出**的请求。
保留当前模型、BF16、MTP3、APC关闭、16384预算、原生调度和graph配置；默认0–3卡/8989，
可加 `--rear-cards` 使用4–7卡/7878。`--plan`只看计划，不加载模型或访问NPU。

## 这次实际测什么

前一份日志只把整个CV核记作1199.604 ms，其中C16约1189.457 ms。本实验在**真实服务的
暖16K prefill C16调用**处取同一组输入：先执行原生产内核，随后执行独立的计时克隆。
两份partial、LSE、status和cluster统计逐字节比较，后续推理继续使用原生产结果。
默认只采每个目标层第一次符合形状的调用，避免每个token都记录。

计时点直接放在AscendC内部，覆盖：

| 阶段 | 要回答的问题 |
|---|---|
| history_load / precise_load | 从压缩历史或精确窗口读取数据花多久 |
| unpack_k / unpack_v | 拆INT2编码、scale/zero重建及舍入转换花多久 |
| bf16_cast | KV、softmax权重、查询及最终旋转输入的BF16发布转换花多久；从发布父阶段中扣除 |
| publish_kv / b1_load | KV操作数发布与送入Cube侧花多久 |
| qk | 相关性矩阵计算花多久 |
| softmax_score_load / softmax_math / softmax_publish_p | 分数读取、掩码/softmax计算、权重发布分别花多久 |
| pv | 加权求值及C16的FP32原子累加花多久 |
| state_restore / state_spill | C16成员累计状态读回/写出花多久 |
| normalize / final_rv / output_publish | 最后归一化、逆旋转和结果写出花多久 |
| cross_core_wait | Cube和Vector互相等待花多久 |
| task/query/init/other | 任务和查询准备、控制及未归类的剩余时间 |

每个Cube及其两个Vector单元都有独立计数区，记录设备时钟和调用次数。嵌套区间扣除
子区间，每个单元检查“各阶段独占时间＋other＝自身总时间”，不靠相位重叠相加凑数。
完整时钟值和各层调用记录落盘，终端只保留关键排行与验证结果。

在本实验限定的910B4上，按同仓原生实现的系统时钟合同（50 ticks/µs）换算诊断毫秒，
同时保留原始cycles。每次还检查单个执行单元的总时长不得超过整核NPU Event时长；
时基检查失败时不发布有效毫秒。这个检查是总时长一致性检查，不是频率校准。

## 怎样读结果

只需复制 `OSCAR_C16_BREAKDOWN_BEGIN` 到 `OSCAR_C16_BREAKDOWN_END`，最多150行/40KiB。
重点看每rank的AIC和AIV阶段排行：

- unpack/softmax大：优先减少向量算术、重建与转换。
- bf16_cast大：优先检查重复舍入和格式转换，不能把它算成搬运。
- history_load/publish/B1/state搬运大：优先调整数据布局、复用和状态周转。
- cross_core_wait大：先分析生产者/消费者的流水依赖，不能直接当成HBM慢。
- qk/pv大：再针对矩阵形状、占用和调用粒度优化。

这些类别按操作语义划分。读取函数也含寻址，转换可能含有限性检查，局部完成屏障
还会等待相应管道；QK/PV的完成时延也包含SDK内部的操作数装载和结果写回。
因此它们不是PMU硬件busy百分比，不能把整个Matmul区间直接叫作纯乘加时间。

## 与原来1199 ms的关系

为测到小步骤的完成时间，计时克隆在局部加入完成屏障，**会改变流水重叠**。
所以同一调用同时记录原核NPU Event总时间、计时核总时间及二者倍率。阶段占比只在
同一个实际执行单元内部比较，不能把不同核的最大阶段时间相加，也不能将占比乘上
旧日志1199 ms来伪造原生产关键路径。

这次输入长度和warm-prefill形状对准前一轮热点，但它是新的真实调用；实际层数、
target/draft调用数和总耗时都以本次记录为准，不预先强制必须17次或必须1199 ms。
目标16个FULL层必须都有记录；draft只列真实观测，不能因缺样本伪造结果。

## 结果与正常推理隔离

- 原C16源码和数学保持，计时克隆由当前源码确定性生成，单独构建/加载。
- 普通 `install_serve.sh` 不开启此实验，也不加载独立计时库。
- 捕图/dummy/短decode不插内部计时；没有HTTP profiler或torch profiler解析阶段。
- 只回读小计数表与校验结果，不把全部KV或partial复制回CPU。
- 计时克隆输出单独分配；临时workspace仅在原核完成后复用。额外输出缓冲占用写入报告。
- 任何输出、状态、计数器、覆盖或资源清理失败都会显示缺口，不能声称已经测完。
