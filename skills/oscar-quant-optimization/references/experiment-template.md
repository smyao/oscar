# 单次量化实验卡

仅在需要新实验时使用；已有报告可直接补缺字段。项目路径相对仓库根，报告与原失败文件保持独立，不创建新的重复档案体系。

## 实验前：把问题与方案分开

- **第一指示对齐**：本实验要定位或消除哪一项“抵消更大batch收益”的主要执行成本？现有证据为何支持优先处理它？写出实际batch、每步有效输出与step时间的影响；若只能证明一个小helper更快，先说明它为何值得进入组合。
- **现存问题**：当前revision/母源hash、实际调用点/路由、对应日志/闭合相位/真实tasks；哪些是观测，哪些是假设。
- **Prefix caching 接缝**：本改动是否影响共享压缩页、精确窗口、快照代际、分叉写或 MTP/GDN 命中边界？说明命中/未命中与释放复用的正确性证据；配对性能注明命中 token，单列快照/恢复开销。
- **方案差分**：只改变什么；保留的FP32/归约顺序/错误域/所有权；来源档案/D.4与SDK接口证据。
- **分母与成本账**：当前已优化基底、形状/并发/source、固定与每KV工作、关键core/依赖DAG；新增workspace、拷贝、屏障及producer成本。列不受影响的阶段与仍未知的占比。
- **量化口径**：完整算子 `S_op=t_base/t_new`。仅对串行、互斥且不重复计费的阶段，`T_pred=T_fixed+Σ(N_i*t_i_new)+新增开销`；整轮对原生 `S_native=T_native/T_pred`，与对当前OSCAR的倍率分母不同。明确配对测量已包含哪些开销，只有未包含的新增开销另加，防止重复扣费。流水按DAG关键路径计算，不求actor/父子相位总和。缺调用数或份额时只给明确条件区间及待补证，不给单点整轮承诺。
- **可达上界**：只优化当前整轮互斥份额`f`时，`S_max_current=1/(1-f)`；若`T_fixed>=T_native/目标倍数`，单独优化该方向不能达标，继续找其他OSCAR主成本。它仍可凭明显净贡献成为组合项，不能把1.8倍writer当成2–4倍native。
- **校准冻结**：先用已有两侧日志及真实工作量约束校准模型，冻结参数后再预测；候选只改变源码证实的成本、任务量或依赖，不为命中目标反调占比/吞吐。MTP接受率对应轮数、native预算对应chunk数量按证据或区间计算；HTTP200、日志prompt吞吐为0不证明请求完成或纯decode阶段。
- **组合判断**：列相对当前组合节省的绝对秒数、比例、适用频度和测量波动/预测区间；未知波动不得写成稳定复现。核对与已选方案重叠/冲突及接入维护成本，再决定本轮纳入、仅作依赖或暂缓。用户现已规定单项 `S_op>=1.15` 可入组合；完整相关路径必须含新增成本并通过精度/协议门。不到门的保留重开条件，不能四舍五入凑15%。正确性/兼容修复和必要依赖不单领倍率；组合相对原生2–4倍，独立倍率不得直接相乘。
- **roofline与decode吞吐账**：分列FULL/全部KV字节、可驻留请求数、实际调度decode batch；列每个有效输出token对应的weights、KV、临时workspace、metadata、MTP访存，以及Cube/Vector工作和同步关键路径。给出原生与组合各自memory/compute-bound的证据或待证范围、MTP输出效率与批次扩张后的计算上限；不能把batch比直接写为吞吐比。对混合prefill/decode与排空阶段另计，不能把稳态decode倍率当成整轮倍率。
- **预声明执行**：同输入/同库/同配置绑定；需要覆盖的oracle/逐位/status/guards/任务计数；完整结果门；期限、空间预算、owned控制文件、日志位置。按改动风险选短/长、K1/多并发、q1/q4/mixed边界，不扩成无穷矩阵。没有阶段因果证据时先采最小必要闭合片段，不盲跑完整大形。
