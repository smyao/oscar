# 一种基于 HBF 的混合注意力模型极低比特前缀缓存管理架构

**技术交底书 · 2026 年 10 月 19 日修订**

本发明围绕两项能力展开：**一是支持极低比特缓存与混合注意力模型的前缀完整续接；二是将原精度保护扩展到选中的历史位置，补偿后续注意力读取这些位置时的 INT2 量化损失。** 两者共用一套 HBF 保存机制：在同一检查点保存完整 SSM 状态和原精度窗口，SSM 与窗口均按间隔 n 保存。

## 一、背景与发明动机

面向长上下文和 Agent 的模型正在采用全注意力与循环状态层相结合的混合架构。与此同时，为降低 KV 缓存的容量和访存开销，已有方案将历史 KV 压缩到 INT2。极低比特量化需要兼顾精度，以 OSCAR 为例，其在线缓存采用三段表示：开头的 **Sink 保留原精度，中间历史使用 INT2，最新的 Recent 窗口保留原精度**。混合模型还需维护各循环层的状态，本文将包含卷积历史等续算必需信息的完整循环状态统称为 **SSM 状态**。[OSCAR](https://arxiv.org/html/2605.17757v1)、[Marconi](https://arxiv.org/abs/2411.19379)

Agent 多轮调用会反复使用已有历史。第一轮处理到 8K token，第二轮在相同的 8K 后追加工具结果和新指令，总输入达到 12K。要从 8K 接着算，全注意力层必须保有对应 KV，循环层也必须取得处理到 8K 时的完整状态。只命中其中一类，不能构成混合模型的完整前缀命中。

三段式缓存还面临另一个问题：为了控制高带宽内存 HBM 的容量和访存开销，原精度保护通常集中于开头和最近窗口。某段工具结果在 6K 时属于 Recent，到了 8K、12K 就进入 INT2 历史；若未保留该段原精度副本，下一轮即使仍需详细引用这段结果，也只能读取有损表示。扩大所有历史的原精度常驻范围，又会削弱极低比特部署原本的容量优势。

HBF 为保留更多原精度数据提供了容量空间，但它的访问与写入方式不同于 HBM，还受到擦写寿命约束。适合本方案的用法是：**保存许多检查点和原精度历史窗口，每次请求只读取命中的状态、必需末窗和少量选中的历史窗口。** 读回后的高频计算仍在 HBM 中完成，HBF 不承担逐 token 的循环状态更新或重复注意力读取。[OCP HBF 规范，§9、§11](https://www.opencompute.org/documents/ocp-hbf-architecture-specification-v0-7-0-final-pdf/)

因此，本发明将两项需求结合起来：为混合模型保留同位置的完整续算信息，同时保留选定检查点的 Recent 原精度副本，使其在窗口前移后仍可作为历史窗口供后续请求使用。

本文的“原精度”指该推理路径在 INT2 量化前保有的 KV 表示，例如 BF16，不表示无限精度，也不表示将整个模型改为 FP32。

## 二、总体布局与保存频率

系统形态为推理引擎中的分层缓存管理模块，由 AICore、HBM、HBF 和前缀目录组成。连接关系为 **AICore ↔ HBM ↔ HBF**。

| 数据 | HBM 中的用途 | HBF 中保存什么 | 保存频率与理由 |
|---|---|---|---|
| **Sink** | 原精度共享常驻，供活动注意力反复读取 | 不保存常规副本 | 兼容前缀形成后保留一份；后续相同前缀直接复用 |
| **INT2 历史及量化参数** | 保留前缀的全量 INT2 副本常驻，新增 KV 增量写入 | 不备份整条 INT2 历史 | 随新内容形成而追加，不因增加检查点重写旧历史 |
| **Recent 原精度窗口** | 当前活动窗口；恢复时用于续接过渡 | 每个检查点对应的原精度窗口 | **每 n 与 SSM 同点保存**，在原精度数据被覆盖前截取 |
| **SSM 状态** | 活动请求的运行状态，按原生精度更新 | 各检查点的完整状态 | **每 n 保存**，必须位于可导出完整状态的已提交边界 |
| **选中的原精度历史窗口** | 只载入本次需要的少量窗口，替代对应 INT2 读取 | 复用已保存的 Recent 窗口，不另复制一份历史 | 请求续接前按需选取，载入后留在 HBM 供后续计算使用 |

**Recent 的活动数据和历史副本有不同访问特征。** 活动 Recent 在窗口内被反复读取，适合 HBM；已离开活动窗口的原精度副本通常不参与计算，只有未来选中时才读回，适合 HBF。SSM 同样如此：当前状态在 HBM 高频更新，历史检查点留在 HBF 等待命中。

HBF 中保存的窗口有两个用途：恢复某个检查点时，它是该点必需的末窗；从更晚的位置续算时，它可以成为补充中间历史精度的窗口。同一份数据通过引用服务这两个用途，无需分别保存两份。

HBM 的“常驻”限定在已接纳前缀的缓存有效期内。它仍承担 Sink 和压缩历史，并预留活动状态、当前窗口及选中历史窗口的工作空间。HBF 不提供无限的活动 HBM 容量。

### n 与窗口宽度分别表示什么

n 是相邻检查点的目标间隔，W 是每个检查点保留的原精度窗口长度。二者不是同一个参数。

本例取 n＝2K、W＝512 token，于 2K、4K、6K、8K 保存四组“SSM＋原精度窗口”。6K 那组保存的 KV 范围是 `[5.5K,6K)`，不是前 6K 全部原精度 KV。保存点之间仍以 INT2 历史为主。

所有保存点都必须能导出对应位置的完整状态。轮次在固定间隔之前结束时，补存实际结束位置，不能为了凑满 n 丢掉最新续接能力。预算不足或某个点被淘汰时，只将仍然完整的检查点列为可命中位置，不承诺任意长度都能零补算。

多个 n 检查点用于支持不同长度的公共前缀。若负载始终只从最新位置连续追加，可以只保留最新状态及有价值的历史窗口，不必无限累积旧状态。

## 三、示例：从 8K 续接到 12K，并恢复 6K 历史的原精度

以下取 1K＝1024 token、Sink＝256、W＝512、n＝2K，均为说明机制的示例参数。

### 3.1 第一轮在原精度仍存在时保存

处理到 6K 时，系统将该点完整 SSM 与 `[5.5K,6K)` 的原精度 KV 保存到 HBF。随后请求继续前进，这段 KV 在活动缓存中退出 Recent，后续按 INT2 读取，但 HBF 中的原精度副本保持不变。

处理到 8K 时，同样保存 SSM 8K 和 `[7.5K,8K)` 的原精度窗口。至此，2K、4K、6K、8K 各检查点均拥有成对的状态和窗口，并引用 HBM 中对应的 Sink、压缩历史和量化参数。

**第一轮结束时，完整保留的数据包括四类：HBM 中覆盖前 8K 的全量 INT2 副本及量化参数、原精度 Sink，以及 HBF 中各检查点的 Recent 原精度窗口和完整 SSM。** 6K 原精度窗口、8K 末窗和 SSM 8K 是下一轮示例选用的部分，并不是已保存数据的全部。

原精度窗口必须从当时仍存在的原始数据截取。把已经量化的 INT2 反量化回 BF16，不能代替这个步骤。本例以全量 INT2 副本作为压缩存储基础，另保留原精度 Sink 和窗口；计算时按区间选择唯一表示，原精度数据覆盖对应 INT2 读取，不重复计入注意力。不要求 token 滑出 Recent 后才首次量化。

### 3.2 第二轮先完成前缀续接

第二轮收到 12K 输入，前 8K 与缓存一致。系统选中完整的 8K 检查点：

1. 复用 HBM 中的原精度 Sink 和覆盖前 8K 的全量 INT2 副本及量化参数。
2. 从 HBF 读回 **SSM 8K** 和 **8K 末窗 `[7.5K,8K)`**，已有有效 HBM 副本则直接复用。
3. 所有相关层和分片就绪后，从 8K 开始处理新增 4K。

8K 末窗负责续接开头的原精度过渡。输入虽然已长达 12K，新增内容最前面的 query 仍位于 8K 附近。按本例窗口规则，第一个新增 query 仍需 511 个旧 token 的原精度 KV，需求随位置前移递减，第 512 个新增 query 起不再需要旧末窗。

这一步解决第一项问题：**全注意力层和循环状态层在同一个位置共同命中，极低比特缓存也能提供完整的续算数据。**

### 3.3 再按需补充中间历史精度

假设第二轮需要引用 6K 附近的一段工具结果，系统在续算前选中 HBF 中已保存的 `[5.5K,6K)` 原精度窗口，将它读入 HBM 的历史窗口工作区。

后续注意力对这一范围使用保存的原精度 K/V，屏蔽对应 INT2 表示；其余历史继续使用 INT2。仍然从 **SSM 8K** 续算，不恢复 SSM 6K。取回 6K 的 KV 是为了改善之后对该段历史的读取表示，不是把模型状态退回 6K。

新增 4K 处理完成后，保留的 12K 缓存视图如下。它描述处理完成后供后续计算使用的表示，不表示新增 4K 在整个 prefill 过程中都按下表量化；当前计算 chunk 仍遵循其既定的原精度路径。

| 范围 | 12K 处理完成后的保留缓存表示 |
|---|---|
| `[0,256)` | 原精度 Sink |
| `[256,5.5K)` | INT2 历史 |
| `[5.5K,6K)` | 从 HBF 取回的原精度历史窗口 |
| `[6K,11.5K)` | INT2 历史 |
| `[11.5K,12K)` | 当前原精度 Recent |

于是，原精度保护不再局限于开头和末尾。**位于上下文中间、被本轮选中的历史窗口，也可以使用原精度数据。** 这一步解决第二项问题：对选中区间，后续访问不再承受其 INT2 存储表示造成的直接误差。

### 3.4 如何选择需要读回的窗口

本实施例采用简单、可解释的选择方式：应用层提供本轮将引用的工具结果或检索内容的 token 区间，缓存管理器与已归档窗口求交，在预设的窗口数量和字节预算内选择需要读回的部分。例中的 6K 是已保存且被本轮引用的位置，不是系统凭空推断出的重要位置。

必要的续接末窗优先于可选的历史窗口。未被保存的区间无法恢复原精度；未被选中的历史仍使用 INT2。选中的窗口进入 HBM 后供后续 query 反复读取，不能每次注意力计算都重新从 HBF 搬运。

## 四、两项优势与精度收益的范围

### 4.1 兼容极低比特与混合注意力的前缀缓存命中

本方案用共同检查点连接三类必需信息：完整循环状态、同位置的原精度末窗，以及仍有效的 Sink 和 INT2 历史引用。只有这些依赖全部有效，才认定该位置可恢复。

若实际共同前缀长 7K，但最近完整检查点在 6K，就从 6K 的状态和窗口继续计算剩余部分，实际省去前 6K 的重复计算。补算和新增内容写入请求自己的 KV 尾页，与新产生的 SSM 保持同一执行分支；未满共享页采用写时复制，不能覆盖旧页或混用原分支的旧后缀。不能将只匹配到的 7K token 都记成已恢复，也不能取 6K 的 SSM 配上 8K 的末窗。

这里的兼容性是指为极低比特 KV 与混合层状态提供完整的共同命中和续算机制，不表示现有部署已经完成所有模型、所有分块方式和所有精度模式的验收。

### 4.2 扩大原精度历史覆盖，补偿部分 INT2 量化损失

INT2 历史无法仅靠反量化找回丢失的信息。HBF 保留的是量化前已经存在的原精度 KV，选中后可以恢复这些保存值，避免后续访问该区间时继续使用 INT2 近似值。与只保留 Sink 和当前 Recent 相比，这为中间历史增加了原精度保护位置，同时无需将全部历史按原精度常驻 HBM。

这个机制恢复的是**所选 KV 在归档时的原精度表示，消除这些位置相对于归档值的 INT2 存储量化误差**。保存的 KV 仍来自当时的计算过程；它本身可能已经受到更早量化计算的影响。读取 6K 原精度窗口不会重新计算 SSM 8K，也不会追溯修改已有隐藏状态或其他历史 KV。

因此，文中不将这种补偿等同于全程 BF16 计算，也不保证任务准确率必然单调提高。实际精度改善的大小，应以同一模型、同一输入和预先确定的质量标准进行验证。

## 五、保存、恢复和精度选择的一致性

### 5.1 同点保存，完整后发布

在每个选定的已提交位置 p，固定各层完整 SSM 和末端 W 个 token 的原精度 KV，并记录它们引用的历史页、绝对位置、有效范围和数据版本。当前接口若只导出 chunk 最终状态，就将保存点安排在可导出的边界，不能假定任意内部位置都已有状态可取。

如果当前请求还要继续计算，先将该点状态和窗口复制到受预算约束的暂存区，复制完成前不允许源数据被更新或复用。随后按 HBF 规定的粒度写入，全部层、并行分片和依赖完成后，才发布可恢复记录。暂停请求也可以保持源数据不变，待写入完成后释放其工作区。

检查点保存的是同一位置的配套数据，不要求它们在同一物理写入指令中完成；完整性由提交记录和完成事件确认。推测解码中未提交的 token、仅被采样但尚未形成状态的 token，不进入共享检查点。

### 5.2 续接与历史精度补充分别管理

恢复记录绑定前缀身份、模型和适配器、输入特征、位置编码、量化及旋转格式、窗口设置、并行分片和必要的计算策略。历史原精度窗口还须与对应压缩历史属于相容的数据来源和执行版本，不能只因 token 位置相同就混用。

续算前确定本次选择的历史窗口集合，在各层使用相同的逻辑范围。注意力为每个位置选择唯一表示：原精度 Sink、当前原精度窗口、选中的原精度历史或 INT2，重叠部分去重，并保留原有因果遮罩。选中窗口使用私有范围映射，不覆盖其他请求正在共享的 INT2 页。

保存新检查点时，一并记录在该位置继续沿用的历史原精度范围映射及对象引用。下一轮若延续同一精度策略，这些依赖也必须完整有效。若改选或取消历史窗口，则记录为从该检查点开始的新策略切换，不能在目录中仍标作原策略的直接延续。

历史原精度补充只对恢复位置之后的新计算生效。它扩展了原来只保护 Sink 和 Recent 的策略，新生成的 KV 和 SSM 使用相应的策略及数据版本；不同精度选择产生的后缀不能仅因 token 序列相同就直接合并。这是从实际保存的检查点继续执行，不等同于用增强策略从头重算整个前缀。

### 5.3 独立回收与存储预算

与只保留当前窗口的方案不同，HBF 中的检查点和原精度窗口是独立保存的历史对象。活动窗口前移不会破坏这些副本，旧检查点可以在预算和依赖允许时继续保留。

原精度窗口既可能被其检查点引用，也可能被更晚请求作为历史精度补充引用，回收前须确认没有有效引用。HBM 中某段必要的 INT2 历史一旦被淘汰，依赖它的检查点也须失去前缀恢复资格。

SSM 与原精度工作区应可独立回收，不能因与保留 KV 共用不可拆分物理页而只完成复制、却未释放 HBM。历史原精度窗口的 HBM 总量受独立预算约束，不能逐步扩张为整段 BF16 历史常驻。

HBF 写入按检查点发生，不随每个 token 对已有检查点原地更新。物理写放大、垃圾回收和刷新仍须计入预算。HBF 是可重建缓存层，不在本实施例中承担永久保存或断电恢复承诺。

## 六、容量与读写成本

设某条兼容前缀保留 m 个检查点，每点完整 SSM 大小为 Q、原精度窗口大小为 A，去重后的 Sink 和 INT2 历史总量分别为 S、B。忽略目录、对齐和物理回收预留：

- **HBF 历史保存量约为 m×(Q＋A)**，适用于 m 组状态与窗口成对保留。若只保留部分状态及更多历史窗口，则分别按实际状态数和窗口数计量；不同版本或分支产生的不同数据也分别计数。
- **HBM 保留 S＋B**，另加活动 SSM、当前 Recent、选中的少量历史原精度窗口和迁移暂存。
- 从 8K 续接且选中 6K 一个历史窗口时，若均不在 HBM，逻辑读回量约为 **Q＋2A**：SSM 8K、8K 末窗、6K 历史窗口。已有有效副本时相应减少，物理读量还受介质粒度影响。

由此，HBF 可以保留许多组数据，而每次只读取恢复必需的一组及少量历史窗口；不是把所有检查点或全部原精度历史搬回 HBM。

n 越小，恢复点和原精度覆盖通常越密，但保存与写入量也越大。在持续接纳检查点的区间，逻辑写入负担约为每 n 个 token 增加 Q＋A。n、窗口宽度 W 和每次选读预算须一起选择，不能因使用 HBF 就忽略寿命和带宽代价。

相对于相同检查点都保留在 HBM，HBF 承担了历史状态和窗口的大部分保存量；相对于只保存最新状态，本方案则主动增加历史存储，以换取更多恢复位置和中间原精度覆盖。这是不同能力之间的取舍，不应混成一个固定的显存节省倍数。

## 七、拟保护的技术组合与已有技术边界

本发明拟保护的组合为：

**在极低比特混合注意力模型的同一已提交前缀位置，按共同间隔 n 保存完整 SSM 和原精度末窗到 HBF，并引用留驻 HBM 的 Sink 与压缩历史；后续请求先按共同位置完成状态与末窗恢复，再按独立预算选取更早的原精度窗口，用于替代对应 INT2 区间参与新的注意力计算；通过范围去重、来源校验和执行版本管理，保持续算与精度选择的一致性。**

这套机制的两个作用相互关联：同点保存提供混合前缀续接所需的完整条件，留下来的原精度窗口又能服务更晚位置的历史精度补充。不能把它拆成“有 HBF 就能命中”或“多读 BF16 就一定提高准确率”两个未经限定的结论。

## 附：实现基础与验证范围

当前工程已有 INT2 格式、原精度窗口、物理页快照和混合状态管理基础。本稿新增的 HBF 检查点管理，以及在历史中间任意指定范围使用原精度 KV 的注意力路径，均属于待实现内容。

- [窗口分段公式](../../oscar_ascend/lifecycle.py#L107)与[当前 candidate 内核](../../csrc/kernels/attention_cv_aligned_cluster4.cpp#L857)支持对续接末窗的需求判断，但不能据此声称已支持任意原精度历史窗口。
- 原生 GDN 接口（本地参考快照 `references/vllm-ascend/vllm_ascend/ops/gdn.py:399`）说明保存点须服从完整状态可导出的边界。
- [既有快照结构](../../oscar_ascend/lifecycle.py#L14)及[故障档案](../../issue1_full_record.md#L14336) #37–49、#127、#128 提供提交位置、数据所有权和物理布局方面的约束依据。

后续验证须分别覆盖：同点完整恢复、范围去重与因果关系、不同精度策略的缓存隔离，以及加入历史原精度窗口后的任务质量。所选 KV 可恢复为保存值，不代表整模精度和性能已通过验证。本轮未连接真机，未做性能测试。
