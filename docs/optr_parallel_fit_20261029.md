# OptR 离线拟合四卡并行（2026-10-29）

用户报告真机准备需要2～3小时，要求优化。当前基底为4204e22，原生采样本来就使用TP4，但后续16层/每层4个KV头的拟合固定在逻辑npu:0，联合输出重放也随层串行。没有本次分阶段计时，不能把全部耗时归给其中一项。

## 实现

- 采样进程退出后，固定candidate自动启动最多四个独立spawn工作进程，每个绑定本次配置的一张卡，默认物理0/1/2/3；显式后四卡仍对应4/5/6/7。NPU精度/编译选项初始化前先选定设备，避免其它worker初始化到逻辑卡0。
- 以完整层为任务，空闲worker动态领取下一层。每层内部仍逐头执行K→V，保持80步、lr、query采样、训练/验证/test、BF16舍入、头组合选择和全部精度阈值。各层使用冻结的原生轨迹，没有跨层优化依赖。最终层顺序按原模型顺序归一。
- 每个worker只加载种子旋转、输出投影和当前层的轨迹，不加载完整模型。每卡一个任务；CPU原始轨迹的峰值最多约为原串行的四层，加上原有拟合暂存，不宣称离线内存零增长。
- CPU线程数按可用CPU affinity分摊并封顶4，interop为1；环境变量只在spawn子进程修改。管道只传任务名与进展，矩阵通过原有原子断点落盘，避免大张量跨进程复制与共享内存生命周期问题。
- 主进程复验每层证书，并等待所有worker以0退出，再执行原有最终认证及原子发布。任何worker失败、证书失败或独立停滞都阻止最终发布；其它worker的进展不能给停滞者续期。
- INT/TERM/HUP以及部分spawn失败均清理本次owned进程；TERM全池宽限5秒后KILL再有界join。创建进程句柄期间屏蔽取消信号，子进程入口解除屏蔽；清理期间重复信号不打断回收。原外层部署总时限和进程组监督保留。未知进程不处理，SIGKILL/掉电等无法执行主机finally的情况不做保证。

档案依据：#94/#95实时错误、#120有界退出、#123设备归属、#166避免fork线程池继承、#172真实进度与断点、#174释放本次进程；本轮不是新增真机故障复验，不追加伪造现场档案。

## 复用与生效

拟合数学和policy不变，完整PT及原生trace身份不变：有效完整PT仍立即复用，不会为并行强制重拟合。未完成任务的新断点绑定新增调度代码哈希，并仅允许认证复用4204e22的v3串行实现哈希`db3b72ec7d53ee57649fff212186d5c8c9a04030fe8e30fb472e17c6c33ce2db`；其余profile、种子、trace、层/head、test-only与文件哈希仍须完全一致，旧v1/v2拟合不能借此混入。

原命令无需参数变化：

```bash
bash scripts/install_serve.sh --variant candidate
```

拟合日志增加`parallel_fit_plan`、`fit_worker_started`、各进展中的`worker/physical_device`、`fit_worker_exited`及`fit_workers_cleanup`。有至少四个待处理层时计划为四worker；全部层已有认证断点时不创建worker。前四卡/7878、服务argv、CANN、MTP/GDN、runtime及timer不变。

按用户要求仅保留本地提交，不推送；远端pull不能据此获得尚未发布的补丁。

## 验证与边界

`tests/test_optr_parallel.py`包含真实四进程同时执行屏障、动态任务分配、exit7失败、拒绝TERM后的KILL清理、单worker停滞而同伴继续工作、信号中断、启动窗口中断、部分spawn失败、认证失败清理、限定旧断点认证，以及真实两层CPU串行/并行拟合→验证→发布→完成层恢复。合成CPU场景中的矩阵和完整精度证书一致，不能外推不同NPU/线程库上的逐位相同。

设备映射检查覆盖前/后四卡的全部逻辑索引及越界拒绝；既有OptR与启动回归、离线wheel及源文件一致性见`reports/optr_parallel_fit_20261029/verification.json`。不连接真机，不做性能实验，不减少训练或跳过检查。收益来源是独立层并发；采样、I/O和收尾仍有不可并行部分，因此不承诺2～3小时固定缩短到某个分钟数，也不申领线上推理性能提升。
